# Brand marks from Simple Icons that Postulo ships, one per line (#654).
# `npm run sync:brands` copies exactly these into src/postulo/static/brands/ and writes
# NOTICE.txt beside them; it exits non-zero on a slug the package no longer has, so an
# upstream removal is decided at the bump and never silent.
#
# A line is `slug` or `slug single-colour <guidelines URL> <what they say>`: the mode
# (TRADEMARKS.md rule 2) is one of
#
#   brand          the owner's published colour, unmodified, and only where it clears 3:1 on
#                  BOTH the white page and the dark one (tests/test_brands.py computes it
#                  from the colour in Simple Icons' data). The default.
#   single-colour  drawn in currentColor, which the stylesheet makes black on the light page
#                  and white on the dark one, and only where the owner's own guidelines
#                  allow a one-colour version. The line records the page and what it says,
#                  and the script refuses the mark without them. Do not add one on the
#                  strength of a guess: a mark whose guidelines cannot be shown to allow it
#                  stays brand-or-none.
#   none           not here at all: the service draws its Lucide icon.
#
# Considered, and why a mark is in none (contrast of its published colour against white /
# against the dark page, and what the owner's page was found to say on 2026-10-05):
#   x          21.0 / 1.0   about.x.com brand toolkit would not be fetched (HTTP 402); nothing shown
#   threads    21.0 / 1.0   Meta's Threads page says nothing on colour versions
#   bitbucket   6.8 / 2.9   Atlassian's page says nothing on colour versions
#   gitlab      2.9 / 7.0   the trademark page had no usable text; nothing shown
#   xing        6.9 / 2.9   dev.xing.com/logo_rules is a 404
#   wikidata    6.3 / 3.2   its official logo is red, green and blue bars; Simple Icons' one-colour 006699
#                           version is a recolouring, and the Wikimedia trademark policy says the logos
#                           "should not be modified without separate permission"; none shown
# Checked again on 2026-10-13 for the service selects (#905), where a coloured mark among
# black ones read as a row of logos; three owners allow black and white, three do not:
#   codeberg    Codeberg/Design publishes the icon in blue and in white only, and its README
#               says "Don't tint the logo in a custom color"; no black version, so none
#   facebook    Meta's logo page allows Facebook Blue or white ("DON'T change the color of the
#               logo"); no black version, so none
#   instagram   Meta's pages offer "full-color (preferred) or monochromatic white"; no black
#               version, so none
# LinkedIn has no mark in Simple Icons any more (removed at its owner's terms, 14.0.0),
# and none is taken from anywhere else (#654).
bluesky single-colour https://bsky.social/about/support/branding "Use a monochrome (black or white) variant when displaying alongside other social media icons"; its don'ts forbid recolouring "other than the approved black and white variants"
mastodon single-colour https://joinmastodon.org/branding "Use a black or white version of the logo when contrast can not be maintained with the main logo"; the page offers the mark alone in purple, black and white
youtube single-colour https://brand.youtube/youtube-icon/ "The logo icon is provided in three color variations: full-color, monochromatic black, and monochromatic white." In those "the triangle in the icon is knocked out so the background shows through", as the Simple Icons path draws it
forgejo single-colour https://codeberg.org/forgejo/meta/src/branch/readme/branding/README.md#logo The branding README lists a "Monochrome version of the logo. SVG version uses `currentColor` to inherit the current text colour."; the logo is CC BY-SA 4.0, attribution given in NOTICE.txt
github single-colour https://brand.github.com/foundations/logo "The Invertocat and our wordmark should only appear in white, black, or in few cases grey or green."
orcid single-colour https://info.orcid.org/documentation/integration-guide/orcid-id-display-guidelines/ "If a specific level of color contrast is required for accessibility reasons then you can use the high contrast black and white icon or the reversed-out white icon on darker color backgrounds." Any other colourway is forbidden.
sourcehut single-colour https://sourcehut.org/logo/ The page publishes the logo in black and in white, and releases it as CC0 ("A circle is not copyrightable. But, if you insist, you may consider these CC-0."); trademark rights are not waived, so it is shown to identify SourceHut only
