{% load i18n postulo %} {% comment %} What a piece of slow work is doing, and what came of it (#247). **A live region, because the change is the whole point.** The state changes under somebody who is not looking at it -- that is what waiting means -- so a live region announces it rather than merely painting it. The region is the page's (`errand.html`), not this fragment's: htmx swaps this element whole on every poll, and a live region inserted with its text already in place is announced unreliably, where text changing inside one that was already there is announced everywhere (#500). **The polling stops when the work does.** `hx-trigger` is only on the unfinished states, so a finished errand is a fragment that asks for nothing. Without htmx there is a link saying *Check again*, which is the same request made by hand: this page is watchable with no script at all, and on an instance with no worker it is already finished on its first paint and the link never appears. **In a dialog (#674)** the same fragment is the body of one: the page's wording changes (*close* rather than *leave*), the finished state ends with *Done* rather than a link, a failure points to the other ways of giving a logo, and the polls ask for the same wording again. It is marked `data-finished` once there is nothing more to wait for, which is what makes the dialog draw the page behind it again when it closes, and `data-focus-result` when the line has just changed under somebody, so that focus goes to it. {% endcomment %}
