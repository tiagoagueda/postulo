{% load i18n %} {% comment %} The job-search report as a document to hand over (#56), set by a theme (#340). A separate template from the page, not a print stylesheet over it. The page is a place to choose a period and follow a link; the document is a fixed thing with a name, a period and the date it was produced on it, because a document with no date is not evidence of anything. Sharing one template would have meant hiding half of each from the other. **Plain values, and no model.** What a report theme is handed is written down in the wiki's *Writing a plugin* and built by `reports.as_context`: the period, the cadence, what happened, the evidence rows, the sources, the industries, the person, the office and the adviser -- strings, numbers, dates, and lists and mappings of them. A theme from a plugin reads the same names this one does, and nothing it is handed can reach the database. **The stylesheet is inline, in the theme's `page_styles`.** Nothing serves this to a browser: it is rendered to a PDF by WeasyPrint in the same process, so it must never fetch anything -- a renderer that reaches the network or the disk for a stylesheet is a renderer that produces a different document depending on where it runs. **Every side is logical.** A report written in Arabic or Hebrew lays out from the other edge, and WeasyPrint honours `dir` on the root element, so `margin-inline-start` is the only kind of margin here. The language and direction are the ones chosen for the report, passed in by the view and the errand alike (`document_language`, `document_direction`), because the errand has no request and so no context processor (#568, #340). **Industries are in the context and not on this page.** They are on the report's page; whether a document prints them is a theme's choice, and Postulo's own two print the report as it always was (#340). {% endcomment %} {{ document_title }} {% block page_styles %}{% endblock %}
