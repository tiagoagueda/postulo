{% load i18n %} {% comment %} The structure every portfolio theme shares (#133). A separate base from `base_cv.html` rather than a flag inside it, because the two differ in the one thing a document's structure is *for*: the order of the argument. A CV is a career read backwards, and the dates carry it. A portfolio leads with the work — what it was, what it points at, what came of it — and the career follows as context. Everything below it is the same machinery: the same `CVItem` selection, the same sections, the same overrides. What changes is which section goes first and how an entry is set. A theme supplies only the stylesheet, which is inlined: the renderer must never fetch anything, so producing a PDF cannot touch the network or the filesystem. {% endcomment %} {% comment %} The title a PDF viewer shows in its title bar and a screen reader announces, so it names the person rather than the shelf: the variant's own name is somebody's private filing -- "Backend, English" -- and the model's help text says as much (#223). {% endcomment %} {{ document_title }} {% if contact %}{% endif %} {% comment %} The nonce is there on the preview page, where a browser's content security policy would otherwise refuse the inlined stylesheet; the PDF renderer is given none and the attribute is left out (#232). {% endcomment %} {% block page_styles %}{% endblock %} {% if contact %}
